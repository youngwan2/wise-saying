## 👁‍🗨 프로젝트 개요
※ 명언은 계속 추가 됩니다. 
- 약 800개가 넘는 명언 목록을 조회하고, 자신만의 명언 카드를 커스텀하여 공유할 수 있는 차분한 앱 디자인 느낌의 웹 사이트
  
## 🎫 프로젝트 목적과 방향성
- [목적] 국내, 국외에도 많은 명언 웹이나 앱이 존재 합니다. 하지만, 너무 번잡하고 광범위한 정보를 다루려다 보니 마음에 드는 명언을 곱심으며 감상하기에는 사용자의 시선을 많이 분산시킵니다. 따라서 저는 마음에 드는 명언을 선택하여 차분한 마음으로 집중할 수 있는 환경을 만들고자 했습니다.

## ⚙ 구현된 기능
|      구현된 기능         | 비고 |
| :------------------: | :------------------ |
|   AI 명언 해설   | 클라이언트로부터 전달된 명언의 id에 일치하는 명언을 DB에서 조회하고, 이를 Open AI 에 요청하여 응답토록 함. 한 번 생성된 해설은 데이터베이스에 저장하여 중복요청을 보내지 않도록 로직 처리 |
|   사용자 명언 등록/수정/삭제 | (유저 서비스) Form Actions 을 통해 전송된 데이터는 서버에서 Joi 를 통해 유효성 검사를 실시하고, 통과된 경우에만 처리되도록 로직 처리 |
| 좋아요 기능 | (유저 서비스) 사용자가 명언 세부페이지에서 '명언( )' 을 클릭하면, 1 이 증가되고, 다시 누르면 제거되도록 로직 구현. |
| 북마크|(유저 서비스) 사용자가 마음에 드는 명언이 있으면 북마크로 등록 후 명언집처럼 활용할 수 있도록 기능 구현 |
|   명언 카드 커스텀 | HTML5 Canvas API 사용. 텍스트 크기, 외곽선, 텍스트 위치 변경, 배경 선택 기능, 사용자 배경 선택 기능, 명언 카드 다운로드 기능 등이 구현됨. 과도한 이벤트 호출을 방지하기 위해서 각 input onChange 이벤트 실행 전 디바운싱 되도록 로직 처리  |
|   명언 공유 | Naver, X, Facebook 공유 가능 |
|  버튼형 무한 스크롤 | NextJS 와의 호환성과 가벼움, 캐싱처리의 목적으로 SWR의 useSWRInfinite 적용. 사용자가 버튼을 클릭해야 추가 데이터를 로드하여 네트워크 리소스가 불필요하게 낭비되는 문제를 방지 |
|  사이트맵 | NextJS sitemap(https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap) 기반으로 모든 데이터 조회 페이지 마다 Sitemap을 생성하고, Google Search Console을 통해 색인 요청이 되도록 함. |
|  JWT 기반 Access + Refresh 토큰 로그인 |JWT 를 기반으로 Access 토큰과 Refresh 토큰 기반의 로그인 기능을 구현. 대략 5~7분 사이를 만료 시점으로 보고, 만료 1분 전에 새로운 토큰을 서버로 부터 재발급 받도록 자동화 기능을 구현 |
|  회원가입 | AWS SES 를 이용한 이메일 본인인증과 개인정보를 취급하는 경우 법적으로 구비해야 하는 필수 서류인 이용약관, 개인정보처리 등을 동의해야 회원가입 가능하도록 로직 처리. 이메일 본인인증의 경우 서버에서 유저의 이메일로 인증번호를 전송하면, 해당 인증번호가 일치해야 다음으로 넘어갈 수 있도록 조건처리 함.  |
|  비밀번호 찾기 | AWS SES 와 JWT AccessToken(임시토큰) 을 사용하여 사용자의 이메일로 임시적으로 활성화된 토큰과 주소를 전달하고, 사용자는 해당 주소를 통해서 비밀번호 변경이 가능함. 이 때, token이 만료되거나 이메일에 전달된 형식이 아닌경우, 더 이상 진행하지 못하게 처리하여 보안을 강화함  |
| 명언 TTS| 사용자가 명언듣기 버튼을 클릭하면, HTML5의 Web Speech API 의 speechSynthesis 과 SpeechSynthesisUtterance 을 통해 생성된 음성을 speak 메소드를 호출하여 실행됨  |
| 명언 TTS 프로그래스| 사용자가 명언듣기 버튼을 클릭하면, 현재 어느 위치까지 진행되었는지를 표시할 수 있는 프로그래스 기능을 구현. |
